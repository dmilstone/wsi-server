Normal monitored release

./ops/wsi-release cycle --tag NAME
./ops/wsi-release cycle --dry-run
./ops/wsi-release cycle --resume
Normal: cycle --tag NAME runs safe phases in order. Diagnostic --step commands are listed under Troubleshooting modes.

Cycle performs repository/environment preflight, all development tests, candidate publication, staging, exact-artifact rehearsal, final preflight, verified production backup/promotion, production QC and optional tagging.

Exact human gates

Development browser QC: y/n
Staging browser QC: y/n
Rehearsal browser QC: y/n
Promotion: y/n
Production browser QC: y/n
Publish saved tag: y/n
Browser success is never inferred. Promotion cannot begin until the complete backup is verified. A failed production start prints rollback guidance and never rolls back silently.
Browser checklist at every environment: banner/title, login, image discovery/open/switch, tiles/pan/zoom, channels/display, full annotation naming/edit/delete/persistence and global Show/Hide, exports, isolated annotation directory, clean console/network, and no sustained unexpected delay.

Troubleshooting and Recovery

Status and verification

wsi production status
wsi staging status
wsi rehearsal status
wsi development status
./ops/wsi-release status
./ops/wsi-release verify staging
./ops/wsi-release verify rehearsal
./ops/wsi-release verify production

Logs

wsi production logs
wsi staging logs
wsi rehearsal logs
wsi development logs

Press Control-C to stop following a log; the server continues running.

Rollback

./ops/wsi-release history
./ops/wsi-release rollback --step
./ops/wsi-release verify production
Rollback restores code/configuration but never restores, replaces or overwrites annotations.

Troubleshooting modes

./ops/wsi-release cycle --step
./ops/wsi-release cycle --resume --step
./ops/wsi-release cycle --resume --verbose
./ops/wsi-release stage --dry-run
./ops/wsi-release stage --step --verbose
./ops/wsi-release rehearse --dry-run
./ops/wsi-release promote --dry-run
./ops/wsi-release history
  • State: .runtime/run/release-cycle.state.
  • Logs: .runtime/log/cycle-*.log.
  • --dry-run: plan only.
  • --step: Enter runs; p repeats; q exits safely.
  • Individual commands are retained for diagnosis and partial reruns.

Stop conditions

  • Dirty Git tree or failed required test
  • Git HEAD differs from staging commit
  • Recorded/calculated SHA-256 differ
  • Staging and rehearsal differ
  • Production backup validation fails
  • Environment identity, marker, root or port mismatch
  • Expected port does not bind
  • New 403, 500 or unhandled JavaScript error
  • Lost annotation or browser regression
  • New/routine delay, blank image or timeout
Timing: the image-switch total ends at OpenSeadragon open and may not include completion of all visible tiles. Use browser Network timing and server logs for repeatable delays.
Privacy: Never copy production slides into development, staging or rehearsal. Verify filenames, metadata, embedded labels, thumbnails, macro images and associated files are deidentified. Never synthesize a missing embedded label/thumbnail from diagnostic pixels.

Manual WSI ingestion

Manual readiness gate: The command is scanner-independent. Confirm the scanner or copy process appears finished before sealing; filesystem stability cannot prove acquisition completeness.

1. Start and prepare one indivisible batch

cd /Users/dm026/Downloads/wsi-server_works
source ops/wsi-ingest.conf
./ops/wsi-ingest status

Place one complete top-level dataset directory beneath /Users/dm026/wsi-ingest-staging. It must contain every .vsi, companion data directory and associated file intended for the batch. Never move a single .vsi without its companion data.

Never reuse a promoted directory name. Use unique names such as 2026-08-05_batch-01 and 2026-08-05_batch-02.

2. Seal and observe

./ops/wsi-ingest inspect DATASET
./ops/wsi-ingest seal DATASET
# Type exactly SEAL

Do not modify the directory after sealing. The seal is observation 1. With validated defaults:

  1. Wait at least 60 seconds.
  2. Run ./ops/wsi-ingest observe DATASET.
  3. Wait at least another 60 seconds.
  4. Run ./ops/wsi-ingest observe DATASET.
  5. Use history to confirm three observations.

3. Preflight, promote and verify

./ops/wsi-ingest promote --dry-run DATASET
./ops/wsi-ingest promote --step DATASET
# Type exactly PROMOTE
./ops/wsi-ingest history
./ops/wsi-ingest status

Before promotion, confirm transaction ID, file count, byte count and absent production destination.

Expected: verified observations 3
sealed_pending_transactions: 0

Allow live discovery to complete or use Refresh images. Confirm every expected image and channel appears.

Stop conditions

  • Scanner or copy activity may continue
  • Companion directory or associated file may be missing
  • Dataset changed after seal
  • Production destination exists
  • File/byte count differs from seal or dry-run
  • Roots missing, nested or on different filesystems
  • Environment markers are wrong
  • Lock held or transaction ambiguous
  • Any command reports FAIL
  • Never use --force or bypass stability
Never manually copy or merge the sealed batch into production. Full design: docs/WSI-INGESTION.md.
